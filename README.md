# Personal site — portfolio + blog

A static Jekyll site built for GitHub Pages. No build step to run, no CI to
configure: push to `main` and GitHub compiles it for you.

## Deploy it (about five minutes)

1. **Create the repo.**
   - *User site* at `https://<username>.github.io` → name the repo
     **`<username>.github.io`**.
   - *Project site* at `https://<username>.github.io/portfolio` → name it
     anything (e.g. `portfolio`).

2. **Push these files to the repo root** (not inside a subfolder):

   ```bash
   git init && git add . && git commit -m "Initial site" && git branch -M main
   ```

   Then add your remote and push.

3. **Turn on Pages:** repo → Settings → Pages → Source: **Deploy from a branch**
   → Branch: `main`, folder `/ (root)`. First build takes a minute or two.

4. **Fix the URLs in `_config.yml`.** This is the step people skip, and it's
   what breaks CSS on a project site:

   | Site type | `url` | `baseurl` |
   |---|---|---|
   | `<username>.github.io` | `https://<username>.github.io` | `""` |
   | project site | `https://<username>.github.io` | `"/portfolio"` |

## Make it yours

Everything personal lives in three places:

| What | Where |
|---|---|
| Name, tagline, email, social links, résumé link | `_config.yml` |
| Homepage bio paragraphs | `index.html` (the `.hero__bio` block) |
| Experience, tools, longer bio | `about.md` |
| Projects — the whole portfolio | `_data/projects.yml` |

Add a project by appending an entry to `_data/projects.yml`; it appears on the
projects page automatically, and on the homepage too if you set `featured: true`.

Drop your résumé at `assets/resume.pdf` (delete the placeholder `.txt` there),
then **uncomment `resume_url` in `_config.yml`**. It ships commented out on
purpose: no file, no link, no 404.

## Write a post

Create `_posts/YYYY-MM-DD-some-slug.md`:

```markdown
---
title: "A title in quotes"
date: 2026-08-21
tags: [postgres, performance]
description: >-
  One or two sentences. Used in the post list and in search-result snippets.
---

Your post, in Markdown.
```

The filename date sets the publish date and the URL (`/blog/some-slug/`). The
post shows up on `/blog/`, on the homepage, and in `feed.xml` on its own.

**Drafts:** put the file in a `_drafts/` folder with no date in the filename.
It won't publish. Preview drafts locally with `bundle exec jekyll serve --drafts`.

## Preview locally

Jekyll 3.9.5 (the version GitHub Pages itself builds with) is already installed
on this machine under `~/.gem`, working around the fact that macOS ships Ruby
2.6. To preview:

```bash
PATH="$HOME/.gem/ruby/2.6.0/bin:$PATH" JEKYLL_NO_BUNDLER_REQUIRE=true jekyll serve --livereload
```

Then open <http://localhost:4000>. Edits rebuild automatically.

Two notes on that command:

- `JEKYLL_NO_BUNDLER_REQUIRE=true` is required because the `Gemfile` declares
  `github-pages`, which isn't installed locally — without it Jekyll tries to
  boot through Bundler and fails. The Gemfile is still worth keeping: it pins
  the versions GitHub Pages actually uses.
- If you later install a modern Ruby (`brew install ruby`, or rbenv), you can
  drop all of that and use `bundle install && bundle exec jekyll serve` instead.

Previewing is optional — GitHub builds the site on push either way.

## What's in here

```
_config.yml          site-wide settings — start here
index.html           homepage: hero, featured projects, recent posts
projects.md          full portfolio, grouped by year
blog.html            post archive, grouped by year
about.md             bio, experience, contact
404.html
_data/projects.yml   portfolio content
_posts/              blog posts (Markdown)
_layouts/            default / page / post page shells
_includes/           head, header, footer, project card, post row, reading time
assets/css/style.css all of the styling, one file
```

## Notes

- **Custom domain:** add a `CNAME` file containing just `www.yourdomain.com`,
  point DNS at GitHub, then set `url` in `_config.yml` to match.
- **Don't add a `.nojekyll` file** — it disables the build this site relies on.
- Light/dark follows the OS by default; the header toggle overrides it and
  remembers the choice in `localStorage`.
- `feed.xml` (RSS), `sitemap.xml`, and social/SEO meta tags are generated by the
  three plugins listed in `_config.yml`. All are on GitHub Pages' allowed list,
  so they work without any CI setup. Adding a plugin *not* on that list means
  switching to a GitHub Actions build.
