I've started and abandoned three blogs. This is the fourth, and the difference
is that I'm lowering the bar on purpose: these are notes, not essays.

The pattern I kept hitting was this — I'd solve something genuinely tricky at
work, write a long internal doc about it, and then watch that doc decay in a
wiki nobody reads. Six months later I'd hit the same class of problem and
rediscover the answer from scratch. Writing it down publicly forces a level of
clarity that internal docs never demanded of me, and it means I can find it
again with a search engine.

**What will be here:** things I had to figure out the hard way. Database
behaviour that surprised me, distributed-systems failure modes, tooling I built
because the existing thing didn't fit, and the occasional post-mortem with the
names filed off.

**What won't:** hot takes on frameworks, and tutorials for things the official
docs already cover well.
